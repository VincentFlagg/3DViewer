**3D Viewer 1.2.0** moves the size limits to the Admin page.

## New

- **Admin → Limits**: three settings that used to need `docker-compose.yml`. Each is in MB, with the size in GB next to it (1024 MB = 1 GB). Changes apply at once, without a restart.

| Setting | Default | What it limits |
|---|---|---|
| Largest file to upload | 1024 MB (1 GB) | One uploaded file. Folders are sent in parts, so their total size has no limit. |
| Largest unpacked .zip | 8192 MB (8 GB) | Everything inside one uploaded .zip. A bigger zip is kept as it is, not unpacked. |
| Largest model to make a thumbnail for | 1024 MB (1 GB) | Bigger models still open in the viewer, but get no server thumbnail. |

- `MAX_UPLOAD_MB`, `MAX_UNZIP_MB` and `MAX_RENDER_MB` in `docker-compose.yml` keep working and win over the Admin page, where they show locked. Remove them there to manage the limits from the Admin page.
- The startup log lists the limits in use, and the README explains them under [Size limits](https://github.com/VincentFlagg/3DViewer#size-limits).

The defaults fit almost every model. Making a thumbnail needs roughly 3 to 5 times the file size in memory, so on a NAS with 4 GB of RAM keep the thumbnail limit at 1024 MB or less.

Also in this version, from 1.1.1: Lychee Slicer scenes (`.lys`) with their supports.

## Update

Pull the new image and redeploy (or `docker compose pull && docker compose up -d`), then hard-refresh your browser. Your libraries, settings, notes and thumbnails are kept.

Image: `ghcr.io/vincentflagg/3dviewer:1.2.0` (or `:latest`), for amd64 and arm64.
